# 플리에 게시물 관리자

별도 CMS 가입이나 상시 서버 없이, 이 PC에서 글을 작성하고 기존 GitHub Pages 홈페이지에 자동 게시합니다. 관리자 아이디는 `plie`이며 Google 계정과 별도입니다. 대여시스템은 이 게시 기능에 포함되지 않습니다.

## 사용

1. 홈페이지 폴더의 **플리에 게시물 관리 실행.cmd**를 더블클릭합니다.
2. 최초 설정 화면에서 관리자 비밀번호를 12자 이상으로 설정합니다. 이후에는 같은 파일로 열고 로그인합니다.
3. 새 게시물을 만들고 글·사진·영상 파일·유튜브 링크를 넣습니다. 순서와 대표 사진을 선택할 수 있습니다.
4. **임시저장**은 PC에만 저장합니다. **홈페이지에 게시**는 공개 대상으로 저장한 뒤 GitHub에 전송합니다.
5. 상단에 **홈페이지 반영을 확인했습니다**가 표시될 때까지 프로그램을 켜 둡니다. 반영에는 몇 분이 걸릴 수 있습니다. 확인 후에는 PC를 꺼도 홈페이지가 계속 열립니다.

- 관리자: http://127.0.0.1:8766/cms/
- 실제 소식: https://www.plierg.com/videos.html
- PC 미리보기: http://127.0.0.1:8766/index.html

일반 관리자 주소에서 최초 설정 안내가 보이면 실행 파일을 다시 더블클릭합니다. 개인 설정용 링크가 자동으로 열립니다. 비밀번호는 해시로 저장되며 외부에 전송하지 않습니다.

## 반영 상태

전송 대기 → 전송 중 → 홈페이지 배포 확인 → 반영 완료 순서입니다. GitHub 전송 성공만으로 반영 완료라고 표시하지 않고, 공개 홈페이지의 배포 식별자를 확인합니다. 실패하거나 10분 안에 확인하지 못하면 안내와 **다시 반영** 버튼을 보여 줍니다. 수정한 글은 PC에 남으며 다시 반영하면 최신 공개 대상으로 재시도합니다.

공개 글을 수정해 임시저장하면 기존 공개본은 유지됩니다. 게시 중단·삭제는 배포가 끝난 뒤 방문자 목록과 글 주소에서 제거됩니다. **이미 공개한 글·파일은 공개 GitHub 저장소의 과거 이력이나 캐시에 남을 수 있습니다.** 민감한 자료의 영구 삭제 용도로 사용하지 않습니다.

## 사진과 영상

사진은 긴 변 2,200px 이하 JPEG로 변환하고 촬영 위치 등 EXIF 메타데이터를 제거합니다. MP4·MOV·WebM은 웹용 H.264/AAC MP4와 표지로 변환합니다. 파일 업로드는 150MB까지, 실제 게시할 변환 결과는 **파일당 80MB**까지 허용합니다. 전체 저장소 파일 합계가 800MB를 넘으면 게시를 멈추고 안내합니다. 큰 영상은 나누거나 유튜브 링크를 넣습니다.

이 수치는 앱의 보수적인 제한입니다. [GitHub Pages 운영 제한](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)도 적용됩니다. 본문에 사용하지 않거나 삭제된 파일의 PC 원본은 실수 복구를 위해 남겨 둡니다.

## 저장과 백업

`cms-app/data/` 전체를 관리자 프로그램을 종료한 상태에서 백업합니다.

- `cms.sqlite3`: 계정·세션·초안·공개 대상으로 선택한 글
- `media/`: 사진·변환 영상·표지
- `incoming/`: 처리 중인 파일
- `publish-config.json`: 게시 대상과 이 데이터 저장소의 식별자
- `publish-status.json`: 최근 전송/배포 확인 상태

비밀번호·초안·설정 키·이 폴더는 Git에 포함되지 않습니다. 공개 홈페이지에는 공개 스냅샷에서 참조한 파일만 내보냅니다. 계정 설정과 원본은 GitHub에서 복구할 수 없으므로 PC 백업이 필요합니다. 다른 PC로 옮길 때는 소스와 **data 전체**를 함께 복구하고 해당 PC에서 GitHub 접근을 설정해야 합니다. Google Drive 저장과 Google 로그인은 사용하지 않습니다.

## 연결 구조

`publisher.py`는 비공개 설정이 켜진 경우에만 실행됩니다. `main`의 최신 내용을 가져오고, 작업 폴더/인덱스와 분리된 임시 Git 인덱스에 아래 파일만 반영합니다.

- `news/<id>.html`: 검색·공유 가능한 완성된 게시물 HTML
- `assets/journal/`: 공개 글이 사용하는 사진·영상
- `content/posts.json`: 공개 목록
- `content/release.json`: 실제 홈페이지 배포 확인용 식별자
- `content/cms-manifest.json`: CMS가 관리하는 파일과 저장소 식별자
- `sitemap.xml`: 기존 주소를 보존한 게시물 사이트맵

강제 푸시하지 않습니다. 다른 사람이 원격을 먼저 수정하면 안전하게 실패하며, 다시 반영하면 최신 원격을 기준으로 만듭니다. 작업 폴더의 대여 개발 코드나 다른 미커밋 파일은 자동 게시하지 않습니다. 다른 데이터 저장소가 기존 게시물을 지우지 않도록 식별자를 검사합니다. 이미 게시한 내용의 현재 파일은 중단 시 제거하지만 Git 이력을 다시 쓰지는 않습니다.

이 PC의 기존 Git 자격 증명을 사용합니다. 브라우저에 GitHub 토큰을 넣지 않습니다. 소스만 받은 환경은 기본적으로 로컬 미리보기이며 자동 게시가 꺼져 있습니다. 별도 상시 서버용 Dockerfile은 참고용으로 유지하며 이번 방식에는 사용하지 않습니다.

## 개발 검증

Python 3.11과 Git이 필요합니다. 사진·영상 라이브러리가 없는 PC에서는 다음 명령으로 설치합니다.

```text
python -m pip install --target cms-app/vendor -r cms-app/requirements.txt
python cms-app/app.py
```

`cms-app/`에서:

```text
python -m unittest -v test_cms.py test_publisher.py
python qa_browser.py
python qa_publishing.py
```

게시 검사에는 임시 로컬 Git 저장소를 사용하며 예시 게시물을 실제 홈페이지에 올리지 않습니다. 브라우저 검사에는 Playwright가 필요합니다.
