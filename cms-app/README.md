# 플리에 게시물 관리

외부 CMS 가입 없이 사용하는 전용 관리자입니다. 현재 로컬 개발 환경에서 동작하며 공개 홈페이지에는 배포하지 않았습니다. 대여시스템과 별도 서버·데이터 폴더를 사용합니다.

## 시작

홈페이지 폴더의 **플리에 게시물 관리 실행.cmd**를 더블클릭합니다.

- 첫 실행: 자동으로 열린 전용 설정 화면에서 관리자 비밀번호를 12자 이상으로 설정합니다.
- 관리자 아이디는 `plie`입니다. 플리에 Google 계정 비밀번호를 요구하지 않는 별도의 관리자 계정입니다.
- 이후 관리자: http://127.0.0.1:8766/cms/
- 홈페이지 미리보기: http://127.0.0.1:8766/index.html
- 방문자 소식 페이지: http://127.0.0.1:8766/videos.html

일반 관리자 주소를 먼저 열어 최초 설정 링크 안내가 보이면 실행 파일을 다시 더블클릭합니다. 설정용 키는 로컬 비공개 데이터 폴더에 보관되고 계정 생성 후 삭제됩니다. URL 조각은 관리 화면이 읽은 직후 주소창에서 제거합니다.

## 글 올리기

1. 새 게시물에서 제목·짧은 소개·분류·지점을 적습니다.
2. 글·소제목·사진·영상 파일·유튜브를 추가합니다. 화살표로 본문 순서를 바꿀 수 있습니다.
3. 본문 사진이나 영상 표지 중 대표 이미지를 고릅니다.
4. 임시저장은 관리자에게만 보입니다. 미리보기로 확인하고 게시하기를 누릅니다.
5. 게시하면 이 CMS 서버의 홈페이지 최근 소식·소식 목록·게시물 주소·사이트맵에 반영됩니다.

이미 공개한 글을 수정해 임시저장하면 방문자는 이전 공개본을 계속 봅니다. 수정 내용 게시를 눌러야 바뀝니다. 게시 중단은 공개본을 내리고 초안을 남기며, 게시물 삭제는 해당 글을 삭제합니다. 게시를 중단한 글에만 사용한 첨부파일은 새 익명 요청으로 열 수 없습니다. 다른 공개 글이 같은 파일을 사용하면 계속 공개됩니다.

## 파일

- 사진: JPG·PNG·WebP 등 Pillow가 읽을 수 있는 이미지. 긴 변 2,200px 이하의 JPEG로 저장하고 EXIF 등 원본 메타데이터를 제거합니다.
- 동영상: MP4·MOV·WebM. 영상 1개씩 FFmpeg로 MP4/H.264/AAC 변환, 자동 표지 이미지 생성, 브라우저 부분 재생 요청 지원.
- 파일당 최대 150MB, 동시에 대기 중인 영상은 기본 3개까지. 처리 시간이 10분을 넘으면 실패로 표시됩니다. 대용량·긴 영상은 유튜브 첨부를 사용할 수 있습니다.
- 유튜브: 일반 영상·짧은 주소·Shorts·live URL을 검증한 뒤 youtube-nocookie 임베드로 표시합니다.
- 업로드한 파일과 변환 작업은 이 서버의 디스크·CPU를 사용합니다. Google Drive에 저장하지 않습니다.

## 저장 위치와 복구

`cms-app/data/cms.sqlite3`에 관리자 비밀번호 해시·세션·게시물·공개본을, `data/media/`에 사진·변환 영상을 저장합니다. `data/incoming/`은 처리 중 임시 파일입니다. 이 폴더를 지우면 내용이 사라집니다. 서버를 종료한 상태에서 **data 폴더 전체**를 백업합니다. 비밀번호 원문을 저장하지 않습니다.

삭제하거나 본문에서 뺀 첨부파일은 실수 복구를 위해 저장소에 남습니다. 현재 자동 정리 기능은 없습니다. 임시 테스트는 별도 임시 폴더를 사용하며 사용자의 데이터에 예시 게시물을 넣지 않습니다.

원본 데이터·설정 키·검증 이미지·라이브러리는 Git 제외 대상이며 정적 미리보기 서버에서 제공하지 않습니다. Sanity 계정·프로젝트·API 키를 만들거나 연결하지 않았습니다.

## 공개 운영 연결

현재 GitHub Pages는 정적 파일만 제공하므로 이 Python 서버와 SQLite·영상 변환 작업을 실행하지 못합니다. **지금 게시 버튼은 로컬 개발 홈페이지에만 반영됩니다.** 실제 자동 반영 운영에는 HTTPS가 있는 상시 서버와 영구 저장 디스크가 필요합니다.

이 서버가 기존 홈페이지 파일도 함께 제공하므로 공개 전환 시 동일한 도메인에서 홈페이지와 `/cms/`를 운영할 수 있습니다. Google 로그인은 연결하지 않았고 자체 관리자 아이디·비밀번호 방식입니다. 기존 대여시스템 주소·Google 설정은 변경하지 않습니다.

준비한 Dockerfile은 운영 검토용이며 이번 환경에서는 Docker 빌드를 실행하지 않았습니다. 실제 호스팅 연결·HTTPS·업로드 제한·백업/복원 확인 전 공개 운영 준비가 완료된 것으로 보지 않습니다.

```text
docker build -f cms-app/Dockerfile -t plie-cms .
docker run --name plie-cms -p 127.0.0.1:8766:8766 -v plie-cms-data:/data -e CMS_PUBLIC_ORIGIN=https://www.plierg.com plie-cms
```

빌드 컨텍스트는 홈페이지 폴더입니다. `.dockerignore`가 실제 데이터와 로컬 라이브러리·대여 개발 폴더를 제외합니다. 실제 HTTPS 역방향 프록시에서 원래 Host를 유지하고 업로드를 최소 150MB까지 허용해야 합니다. 관리자 쿠키는 HTTPS 운영에서 Secure가 켜집니다. 초기 설정 키는 서버 관리자가 비공개 볼륨의 `.setup-key`를 읽어 최초 설정 화면에 전달해야 합니다. 초기 설정을 외부 방문자에게 공개적으로 허용하는 기능은 없습니다.

## 개발 확인

Python 3.11에서 설치·검증했습니다. 이 작업 폴더에는 `vendor/` 라이브러리가 설치되어 있습니다. 다른 PC에서는 다음 명령으로 준비합니다.

```text
python -m pip install --target cms-app/vendor -r cms-app/requirements.txt
python cms-app/app.py
```

`cms-app/`에서:

```text
python -m unittest -v test_cms.py
python qa_browser.py
```

서버 검증 6개(권한·CSRF·초안 비공개·공개 스냅샷·충돌·사진 접근·실제 영상 변환·입력 검증), 실제 Chromium 브라우저 흐름 10개, 모바일 화면 확인을 통과했습니다. 브라우저 검증에는 Playwright가 필요합니다. 실제 공개 서버나 외부 서비스에 게시하지 않습니다.
